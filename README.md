# StandoffShop

Интернет-магазин цифровых товаров и игровых услуг. Проект независимый и не связан с разработчиками Standoff 2.

**Текущая версия: 0.8.0 — Order Management 2.0.** Реальные платежи и автоматическая выдача отключены.

## Новое в v0.8.0

- Очередь исполнения заказов `/admin/queue` с задачами по каждому товару и назначением исполнителя.
- Журнал событий, внутренние заметки сотрудников и сообщения покупателям.
- Клиентские страницы `/account/orders/[id]` и `/account/notifications`.
- Приватная загрузка PDF, PNG, JPG и TXT для выполненных заказов, с проверкой оплаты и владельца.
- Автоматический отзыв скачивания при возврате, проверка SHA-256.
- Новая Prisma-миграция без удаления прежней истории.

**Миграция с v0.7.0:** сделайте резервную копию PostgreSQL и медиа. Затем в прежнем Docker Compose-проекте запустите `npm ci`, `npx prisma generate`, `npm run db:migrate`. Подробная документация: [управление заказами](docs/ORDER-MANAGEMENT.md), [изменения v0.8.0](docs/RELEASE-0.8.0.md).

## Запуск на Windows

Понадобятся Node.js 22+, Docker Desktop с запущенным движком и npm.

1. Скачайте исходники репозитория и откройте терминал в корне проекта.
2. Создайте `.env` из шаблона: `copy .env.example .env` (в PowerShell: `Copy-Item .env.example .env`).
3. Откройте `.env` и установите собственный случайный `SESSION_SECRET` длиной не менее 32 символов. Не публикуйте файл.
4. Запустите PostgreSQL: `docker compose up -d`.
5. Установите зависимости: `npm ci`.
6. Проверьте схему: `npx prisma validate`.
7. Создайте клиент: `npx prisma generate`.
8. **На новой пустой БД:** примените миграции `npm run db:migrate`. При обновлении старой БД используйте [документацию](docs/DATABASE.md). Не удаляйте Docker-том.
9. Запустите: `npm run dev`. Адрес: http://localhost:3000.

Для пробной категории и двух **неопубликованных** товаров можно выполнить `npm run db:seed`. Все пробные позиции создаются со статусом `DRAFT` и не появятся в каталоге, пока вы их не опубликуете.

**Для админки Prisma Studio не нужна.** На сайте есть собственный интерфейс `/admin` с отдельными страницами товаров, категорий, заказов и покупателей.

### Первое назначение администратора

Сначала зарегистрируйте свой аккаунт через `/account`. Войдите в PostgreSQL:

```cmd
docker compose exec postgres psql -U standoffshop -d standoffshop
```

Внутри PostgreSQL выполните, подставив email своего аккаунта:

```sql
UPDATE "User" SET role = 'ADMIN' WHERE email = 'you@example.com';
```

Выйдите через `\q`, откройте `/account` и при необходимости перелогиньтесь. После этого появится кнопка входа в панель администратора.

### Что можно делать в /admin

- **Обзор:** сводка по товарам, заказам и покупателям.
- **Товары:** создание, SKU, варианты, характеристики, изображения и галереи, предпросмотр, массовое управление статусами.
- **Категории:** корневые категории и подразделы (до двух уровней), редактирование и безопасное удаление.
- **Заказы:** поиск, история событий, внутренние заметки, сообщения покупателю, проверяемые переходы статусов.
- **Очередь:** задачи по позициям заказа, исполнитель, статусы, защищённое завершение исполнения.
- **Материалы:** приватная загрузка и публикация файлов после выполнения заказа, отзыв при возврате.
- **Аудит:** журнал изменений товаров, категорий, заказов и тестовых платежей.
- **Покупатели:** поиск и просмотр списка без доступа к паролям.
- **Главная страница:** редактирование первого экрана и фонового изображения в `/admin/content`.

В системе нельзя пометить заказ оплаченным вручную. Приём платежей появится только после подключения проверенного платёжного провайдера. Сейчас можно создать неоплаченный демо-заказ.

## Локальное тестирование оплаты

Для тестовой оплаты в режиме разработки в `.env` можно добавить:

```dotenv
PAYMENT_SANDBOX_ENABLED="true"
PAYMENT_SANDBOX_SECRET="СЕКРЕТ_ДЛИНОЙ_НЕ_МЕНЕЕ_32_СИМВОЛОВ"
```

Сгенерируйте отдельный криптографически случайный секрет:

```cmd
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Перезапустите `npm run dev`. Откройте `/admin/orders` и выберите неоплаченный заказ — появится управление **SANDBOX**. Оплата и возврат только имитируются, деньги не списываются. **Не используйте sandbox для реальных продаж.** Даже с флагом включения sandbox недоступен в production.

## Команды

| Команда | Назначение |
|---|---|
| `npm run dev` | Локальный Next.js |
| `npm run build` | Production-сборка |
| `npm run typecheck` | Проверка TypeScript |
| `npm test` | Проверка бизнес-правил, валидации и подписи событий |
| `npx prisma validate` | Проверка схемы |
| `npm run db:push` | Экспериментальная синхронизация без миграции (не для рабочих баз) |
| `npm run db:migrate` | Применение версионированных миграций Prisma |
| `npm run db:status` | Проверка состояния миграций |
| `npm run test:security` | Интеграционные security-тесты при запущенном сервере и PostgreSQL |
| `npm run test:orders` | Интеграционные тесты обработки заказов (dev + sandbox) |
| `npm run db:seed` | Две демо-позиции в черновиках |

## Перед публичным запуском

В 0.7.0 добавлены инструменты управления каталогом и загрузка изображений на локальный диск. По-прежнему отсутствуют MFA, подтверждение email, полноценное восстановление доступа, фоновое исполнение заказов, постоянный объектный storage для облачного deployment и реальный эквайринг. Не используйте эту версию для реальных продаж. Требуются ограничения запросов, e2e-тесты и проверка правил Standoff 2 и юридических требований.
