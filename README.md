# StandoffShop

Интернет-магазин цифровых товаров и игровых услуг. Проект независимый и не связан с разработчиками Standoff 2.

**Текущая версия: 0.5.0 — Monochrome UI.** Реальные платежи и автоматическая выдача отключены.

## Новое в v0.5.0

- **Единая чёрно-белая тема** для главной страницы, каталога, карточки товара, корзины, личного кабинета и административной панели.
- **Новая главная:** контурная надпись, крупный заголовок, преимущества и сценарий оформления.
- **Поиск в шапке:** модальное окно, сочетания `Ctrl+K` / `Cmd+K` и `Esc`.
- **Интерактив:** состояния кнопок и форм, анимации карточек, индикатор товаров в корзине, адаптивное мобильное меню.
- **Состояния интерфейса:** загрузка, пустые экраны, успешное добавление товара, ошибка и 404.
- **Доступность:** контраст, клавиатурные фокусы и отключение длительных анимаций при `prefers-reduced-motion`.

Реальные платежи и выдача товаров по-прежнему отключены. Дизайн полностью работает без внешних изображений; фотография товара опциональна.

Подробнее: [описание релиза v0.5.0](docs/RELEASE-0.5.0.md) и [визуальная система](docs/DESIGN-SYSTEM.md).

## Что добавлено в v0.4.0

- Идемпотентное оформление: `Idempotency-Key` предотвращает повторное создание заказа после таймаута или повторного клика.
- Серверный журнал `PaymentAttempt` / `PaymentEvent`, проверка подписанных webhook-событий и безопасные переходы статусов.
- Локальный sandbox с тестовыми оплатой и полным возвратом, доступный только ADMIN при включении настроек разработки. В production полностью выключен.
- Проверки подписи, повторной доставки события, суммы, валюты, времени и жизненного цикла заказа.
- Расширенный GitHub CI: unit tests, Prisma, TypeScript, production build, PostgreSQL smoke и dev-sandbox integration.

**Реальный эквайринг не подключён.** Подробнее: [документация платежей](docs/PAYMENTS.md), [список изменений v0.4.0](docs/RELEASE-0.4.0.md).

## Запуск на Windows

Понадобятся Node.js 22+, Docker Desktop с запущенным движком и npm.

1. Скачайте исходники репозитория и откройте терминал в корне проекта.
2. Создайте `.env` из шаблона: `copy .env.example .env` (в PowerShell: `Copy-Item .env.example .env`).
3. Откройте `.env` и установите собственный случайный `SESSION_SECRET` длиной не менее 32 символов. Не публикуйте файл.
4. Запустите PostgreSQL: `docker compose up -d`.
5. Установите зависимости: `npm install`.
6. Проверьте схему: `npx prisma validate`.
7. Создайте клиент: `npx prisma generate`.
8. Примените модель данных: `npm run db:push`.
9. Запустите: `npm run dev`. Адрес: http://localhost:3000.

Для пробной категории и двух **неопубликованных** товаров можно выполнить `npm run db:seed`. Все пробные позиции создаются со статусом `DRAFT` и не появятся в каталоге, пока вы их не опубликуете.

**Для админки Prisma Studio не нужна.** На сайте есть собственный интерфейс `/admin` с отдельными страницами товаров, категорий, заказов и покупателей.

### Первое назначение администратора

Сначала зарегистрируйте свой аккаунт через `/account`. Войдите в PostgreSQL:

```cmd
docker compose exec postgres psql -U standoffshop -d standoffshop
```

Внутри PostgreSQL выполните, подставив email своего аккаунта:

```sql
UPDATE "User" SET role = 'ADMIN' WHERE email = 'you@example.com';
```

Выйдите через `\q`, откройте `/account` и при необходимости перелогиньтесь. После этого появится кнопка входа в панель администратора.

### Что можно делать в /admin

- **Обзор:** сводка по товарам, заказам и покупателям.
- **Товары:** создание, изменение, поиск, фильтрация, цена, изображение по HTTPS-ссылке, черновик / публикация / архив.
- **Категории:** создание, редактирование, удаление пустых категорий.
- **Заказы:** поиск, просмотр состава и ручные переходы статусов только там, где это безопасно.
- **Покупатели:** поиск и просмотр списка без доступа к паролям.

В системе нельзя пометить заказ оплаченным вручную. Приём платежей появится только после подключения проверенного платёжного провайдера. Сейчас можно создать неоплаченный демо-заказ.

## Локальное тестирование оплаты

Для тестовой оплаты в режиме разработки в `.env` можно добавить:

```dotenv
PAYMENT_SANDBOX_ENABLED="true"
PAYMENT_SANDBOX_SECRET="СЕКРЕТ_ДЛИНОЙ_НЕ_МЕНЕЕ_32_СИМВОЛОВ"
```

Сгенерируйте отдельный криптографически случайный секрет:

```cmd
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Перезапустите `npm run dev`. Откройте `/admin/orders` и выберите неоплаченный заказ — появится управление **SANDBOX**. Оплата и возврат только имитируются, деньги не списываются. **Не используйте sandbox для реальных продаж.** Даже с флагом включения sandbox недоступен в production.

## Перед публичным запуском

В 0.5.0 по-прежнему нет полноценной защиты от перебора паролей и спама, подтверждения email, восстановления доступа, фонового выполнения заказов, аудита действий администратора, механизма загрузки изображений и подключённого эквайринга. Не используйте эту версию для реальных продаж. Требуются ограничения запросов, e2e-тесты и проверка правил Standoff 2 и юридических требований.
