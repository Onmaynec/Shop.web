# StandoffShop v1.0.0 — Platform Release

**Статус:** релиз приложения для локального использования, тестовых заказов и демонстрации возможностей. Это не разрешение запускать коммерческую витрину с реальными платежами.

## Безопасность аккаунта

- Добавлена двухфакторная аутентификация TOTP для любого зарегистрированного аккаунта, в том числе сотрудников и администраторов.
- Настройка через `/account/security`: подтверждение текущего пароля, секрет для приложения-аутентификатора, проверка шестизначного одноразового кода.
- Поддерживаются Google Authenticator, Microsoft Authenticator, Aegis и другие TOTP-приложения. Встроенной отправки SMS нет.
- TOTP-секрет шифруется с помощью AES-256-GCM, ключ выводится из `SESSION_SECRET`; в БД не хранится открытый секрет.
- Вход с включённой MFA требует корректный одноразовый код либо один из восьми резервных кодов.
- Одноразовые коды защищены от повторного использования на уровне обновления записи БД. Использованные резервные коды удаляются атомарно.
- При включении MFA завершаются остальные активные сессии. При отключении необходимы текущий пароль и действующий второй фактор.
- Настройка MFA ограничена по времени и количеству попыток.
- Политика `ENFORCE_STAFF_MFA=true` на стороне сервера ограничивает доступ сотрудников к привилегированным функциям до завершения настройки MFA.

## Избранное

- Пользователь может добавить товар в избранное со страницы товара.
- Отдельная страница `/account/favorites` сохраняет предложения между устройствами и сессиями через PostgreSQL.
- Избранное доступно только владельцу аккаунта; чужие сохранённые товары не выдаются.
- Архивные товары помечаются как недоступные и могут быть удалены из сохранённого.
- Сервер повторно проверяет статус товара и ограничивает число сохранённых позиций.

## Стабильность и готовность магазина

- В админке появился `/admin/readiness` с диагностикой PostgreSQL, миграций, конфигурации сессий, политики MFA, sandbox и известных блокеров запуска.
- Исправлена формулировка финансового показателя в обзоре: заказы в «оплаченных» статусах не считаются выручкой и могут включать тестовые операции.
- Обновлена чёрно-белая дизайн-система для избранного, панели MFA, мобильной навигации и диагностики.
- Добавлены модульные тесты TOTP и шифрования, а также интеграционный сценарий MFA, восстановления, отзыва сессий и избранного.

## Новая схема данных

Миграция `20261114100000_platform_release`: дополнительные поля MFA в User, таблицы `MfaRecoveryCode` и `Favorite`. Все ранее существующие заказы, пользователи, товары, роли и платежи остаются в базе. При первом запуске MFA **выключена** у всех аккаунтов, избранное пустое.

## Ограничения

- Эквайринг по-прежнему не подключён. Реальная выдача, автоматическое подтверждение оплаты и коммерческие продажи недоступны.
- Нет SMTP и email-верификации, восстановления аккаунта через почту, независимого security review и полноценного production object storage.
- Настройка MFA выполняется вручную с текстовым ключом, без QR-кода. Отдельное управление устройствами и поддержка WebAuthn не реализованы.
- `ENFORCE_STAFF_MFA` выключена по умолчанию, чтобы миграция не заблокировала существующих администраторов. На защищённом окружении включайте её **после** настройки факторов сотрудников.
- При утрате `SESSION_SECRET` расшифровать ранее включённые TOTP-секреты уже нельзя, поэтому храните секрет в защищённом резервном хранилище и планируйте его ротацию с повторной настройкой MFA.
- Независимо от номера версии нужен отдельный допуск к коммерческой эксплуатации, юридическая и инфраструктурная проверка.
