# StandoffShop — миграции и резервное копирование (v0.6.0)

**Прочитайте перед запуском на существующей базе.** В v0.5.0 база обычно создавалась через `prisma db push` без `_prisma_migrations`. В v0.6.0 добавлены две версионированные миграции: baseline старой модели и новые таблицы безопасности.

## 1. Резервная копия на Windows

Остановите сервер Next.js, но оставьте Docker с PostgreSQL запущенным. В PowerShell из той же директории Compose-проекта, где находится существующая база:

```powershell
docker compose ps
powershell -ExecutionPolicy Bypass -File .\scripts\Backup-StandoffShop.ps1
```

Сценарий создаёт `pg_dump -Fc`, проверяет архив командой `pg_restore --list`, копирует его в `backups/` и проверяет, что файл не пуст. **Не публикуйте копии базы**, там персональные данные пользователей.

Восстановление необходимо проверять в **отдельной тестовой базе**. Никогда не запускайте восстановление поверх действующей базы магазина без проверенного плана.

При изменении каталога извлечённых файлов ZIP убедитесь, что используется тот же Docker Compose project name и тот же том PostgreSQL. Создание новой Compose-папки с другим именем часто приводит к созданию нового пустого тома.

## 2. Обновление существующей БД с v0.5.0

Этот порядок относится к базе, где уже существуют таблицы v0.5.0, но ещё нет таблиц `Session`, `RateLimitBucket` и `AuditLog`.

1. Сделайте и проверьте резервную копию.
2. Обновите исходники v0.6.0, выполните `npm install`, `npx prisma generate`.
3. **Только для старой базы** отметьте первоначальную миграцию применённой:

```cmd
npx prisma migrate resolve --applied 20261114000000_baseline
```

4. Примените изменения v0.6.0:

```cmd
npm run db:migrate
npx prisma migrate status
```

Команда `migrate deploy` создаёт только новые таблицы v0.6.0, не удаляя пользователей, товары и заказы.

**Не запускайте baseline SQL на существующей базе**: эти таблицы уже есть. `migrate resolve` только записывает факт применения baseline в историю миграций; поэтому перед ним важно проверить состояние старой схемы.

Если миграция уже применялась через `db push` и новые таблицы существуют, **не запускайте её повторно**. Сначала сравните структуру с миграцией и пометьте `20261114060000_security_stability` применённой через `migrate resolve --applied` только после проверки. При несовпадениях остановитесь и устраните расхождение.

## 3. Чистая установка

Если база ещё не содержит таблиц приложения:

```cmd
docker compose up -d
npm install
npx prisma generate
npm run db:migrate
npm run dev
```

Обе миграции применятся последовательно. Для демонстрационного каталога при необходимости выполните `npm run db:seed`.

`db:push` оставлена для экспериментальной разработки, но для обновления рабочих баз предпочтительнее `db:migrate`.

## 4. Ротация сессий

Формат cookie изменился в v0.6.0. Старые cookies перестанут давать доступ, пользователям потребуется войти повторно. `SESSION_SECRET` должен оставаться случайным, неизменным и недоступным третьим лицам: его замена инвалидирует новые сессии.

## 5. Уход за БД

Файл `scripts/cleanup-storage.sql` удаляет давно истёкшие счётчики и сессии. Запускайте его вручную после проверки срока хранения:

```cmd
docker compose exec -T postgres psql -U standoffshop -d standoffshop -f /dev/stdin < scripts/cleanup-storage.sql
```

Содержимое `AuditLog` и `PaymentEvent` автоматически не удаляется. Политика хранения и экспорт должны быть согласованы до production.

## 6. Проверки после обновления

```cmd
npx prisma migrate status
npm run typecheck
npm test
npm run build
```

После запуска сайта проверьте регистрацию/вход, завершение сессий, администратора, корзину, тестовый неоплаченный заказ и журнал аудита.

## Обновление v0.6.0 → v0.7.0

На базе с уже применённой миграцией `20261114060000_security_stability`:

1. Остановите Next.js, сохраните `SESSION_SECRET` и сделайте резервную копию PostgreSQL.
2. Если использовались локальные изображения — сохраните отдельно папку `MEDIA_STORAGE_DIR` или `data/media`.
3. В старом Docker Compose-проекте выполните `npm ci`, `npx prisma generate`, `npm run db:migrate`.
4. Проверьте `npm run db:status`. В базе должна появиться миграция `20261114070000_catalog_pro`.
5. Запустите `npm run dev`. В `/admin/products` доступны галереи и варианты, в `/admin/content` — оформление главной страницы.

**Не выполняйте `migrate resolve --applied 20261114000000_baseline` повторно**, если миграции уже были применены в v0.6.0. Не используйте `docker compose down -v`.

Если файлы хранятся на внешнем диске, можно задать абсолютный путь через `MEDIA_STORAGE_DIR` в `.env`. Он должен быть доступен на запись серверному процессу Next.js. Для резервного копирования медиафайлов требуется отдельная процедура: дамп PostgreSQL содержит только адреса изображений.

## Обновление v0.7.0 → v0.8.0

Сохраните резервные копии PostgreSQL и локальных файлов. Директория `data/deliveries` или `PRIVATE_DELIVERY_DIR` **не включается в дамп PostgreSQL**, её нужно архивировать отдельно. Остановите Next.js и выполните из прежней папки:

```cmd
docker compose up -d
npm ci
npx prisma generate
npm run db:migrate
npm run db:status
npm run dev
```

Миграция `20261114080000_order_management` добавляет `OrderActivity`, `OrderTask`, `OrderDelivery`, `CustomerNotification`. Для старых заказов создаётся запись о текущем статусе на момент миграции. Пользователи, товары, заказы и их стоимость не удаляются. **Не используйте `docker compose down -v`**.

Доступ к выдаче файлов только у привязанного к заказу аккаунта, не по совпадению email. Подробнее в [ORDER-MANAGEMENT.md](ORDER-MANAGEMENT.md).

## Обновление v0.8.0 → v0.9.0-rc.1

**Перед началом:** остановите Next.js, сделайте резервную копию PostgreSQL, отдельно сохраните папки `data/media` и `data/deliveries` либо их альтернативные пути из `.env`. Не удаляйте том Docker.

В прежнем проекте после обновления исходников:

```cmd
docker compose up -d
npm ci
npx prisma generate
npm run db:migrate
npm run db:status
npm run dev
```

Миграция `20261114090000_support_operations` добавляет роли SUPPORT/FULFILLMENT и таблицы `SupportTicket`, `SupportMessage`. **Никому не выдаётся роль автоматически**: существующие администраторы и покупатели сохраняют свои права. Назначайте новые роли только из `/admin/staff`. При смене роли сессии пользователя отзываются.

Это предрелизная версия, не размещайте её на публичном коммерческом сервере без отдельной проверки безопасности.

## Обновление v0.9.0-rc.1 → v1.0.0

Сначала остановите Next.js, сделайте проверенный backup PostgreSQL, сохраните `.env`, `data/media`, `data/deliveries`. **Не удаляйте Docker-том** и не меняйте значение `SESSION_SECRET`: теперь от него также зависит шифрование секретов MFA.

После обновления исходников из прежней папки:

```cmd
docker compose up -d
npm ci
npx prisma generate
npm run db:migrate
npm run db:status
npm run dev
```

Миграция `20261114100000_platform_release` добавляет поля User для TOTP, таблицы `MfaRecoveryCode` и `Favorite`. Это аддитивное изменение: прежние пользователи, роли, заказы, оплаты и файлы не удаляются. MFA не включается принудительно при миграции.

Чтобы не заблокировать действующую команду, сначала настройте MFA всем сотрудникам в `/account/security`, затем включайте `ENFORCE_STAFF_MFA=true` на сервере (см. [SECURITY-MFA.md](SECURITY-MFA.md)).
