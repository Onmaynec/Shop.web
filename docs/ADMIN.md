# Административная панель StandoffShop

## Доступ

Адрес: `http://localhost:3000/admin`.

Права проверяются на сервере. Все API управления каталогом и заказами требуют роль `ADMIN`. Новые аккаунты получают роль `CUSTOMER`. Первого администратора назначают локально через PostgreSQL, как описано в README. Публичного endpoint для выдачи роли ADMIN нет.

## Каталог

`/admin/categories` — создание, переименование и удаление пустых категорий. Существующую категорию с товарами удалить нельзя.

`/admin/products` — поиск по названию и slug, фильтр статуса, постраничный список, создание и редактирование. Параметры: название, slug, категория, цена в рублях, описание, статус, HTTPS-адрес изображения. Сервер преобразует и проверяет цену в копейках. Архивирование скрывает товар из публичного каталога, но не удаляет старые позиции заказов.

Для локальной проверки выполните `npm run db:seed`, затем в админке переведите демо-товар из `DRAFT` в `ACTIVE` — он появится в каталоге. Содержимое пробных товаров явно помечено как демонстрационное.

## Заказы

`/admin/orders` — фильтрация по статусу, поиск по номеру или email, детали, цены и состав из сохранённого снимка заказа.

Разрешённые ручные переходы:

- `PENDING_PAYMENT → CANCELLED`.
- `PAID → PROCESSING`.
- `PROCESSING → FULFILLED`.

В текущей версии платежи отключены, поэтому реальные заказы не могут получить статус `PAID`. Включать его через SQL или публичный endpoint нельзя.

## Покупатели

`/admin/customers` — список аккаунтов, email, роль, дата регистрации и количество заказов. Функций смены роли и удаления пользователей из интерфейса пока нет.

## Ошибки и ограничения

Ответы API содержат сообщение об ошибке и HTTP-статус. При дублировании slug возвращается 409, некорректных данных — 400, нехватке прав — 403. Меняющие данные запросы проверяются на допустимое происхождение.

Действия пока не записываются в журнал аудита; нет контроля запасов, загрузки файлов, массового редактирования, промокодов и ограничения частоты запросов. Не публикуйте проект как производственный магазин без следующего этапа безопасности.

## Аудит v0.6.0

Раздел `/admin/audit` показывает журнал операций. Сервер сохраняет ID администратора, тип действия и краткие безопасные сведения. Запись журнала и изменение товара, категории или статуса заказа фиксируются в одной транзакции. Удалять журнал из интерфейса нельзя.

## Catalog Pro v0.7.0

Товары поддерживают галереи, характеристики, теги, SKU и активные ценовые варианты. В разделе `/admin/products` есть копирование карточки, предпросмотр черновика и массовое изменение статусов. Новый раздел `/admin/content` управляет первым экраном главной страницы. Категории поддерживают два уровня. Подробнее: [CATALOG-PRO.md](CATALOG-PRO.md).

## Order Management v0.8.0

В `/admin/orders` доступны история, внутренние заметки и клиентские сообщения, загрузка/публикация приватных файлов. `/admin/queue` — очередь задач, которые создаются после проверенного платежа. Без завершённых задач нельзя переводить заказ в `FULFILLED`. Выдача файлов требует отдельной публикации; sandbox используется только локально. Подробности: [ORDER-MANAGEMENT.md](ORDER-MANAGEMENT.md).

## v0.9.0-rc.1 — сотрудники, поддержка и операции

В `/admin/staff` ADMIN может назначать SUPPORT/FULFILLMENT и другие роли; сессии сотрудника отзываются. `/admin/support` — очередь обращений с приоритетами, публичными ответами и внутренними заметками. `/admin/queue` — задачи исполнителей; `/admin/queue/<orderId>` — загрузка результата назначенным исполнителем без публикации. `/admin/operations` — показатели и аудитируемый экспорт CSV.

Сотрудники не получают права на каталог, платёжный sandbox и управление ролями автоматически. Проверки выполняются сервером. Подробнее: [SUPPORT.md](SUPPORT.md) и [OPERATIONS.md](OPERATIONS.md).
