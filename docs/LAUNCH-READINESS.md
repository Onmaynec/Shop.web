# StandoffShop — проверка перед публичным запуском

Панель `/admin/readiness` показывает только те факты, которые может проверить работающий сервер. **Это не автоматический допуск к эксплуатации.**

## Перед локальным обновлением с v0.9.0-rc.1

1. Остановите Next.js и создайте PostgreSQL backup. Сохраните `data/media` и `data/deliveries`, если использовались файлы.
2. Важно сохранить текущий `.env`, в первую очередь `SESSION_SECRET`.
3. Обновите исходники из релиза. Не удаляйте volume PostgreSQL и не запускайте `docker compose down -v`.
4. Выполните:
   ```cmd
   docker compose up -d
   npm ci
   npx prisma generate
   npm run db:migrate
   npm run db:status
   npm run dev
   ```
5. Проверьте `/api/health`, `/admin/readiness`, `/account/security` и `/account/favorites`.
6. Настройте MFA для сотрудников. При необходимости после этого включите `ENFORCE_STAFF_MFA=true`.
7. Откройте историю заказов и поддержки, проверьте, что ранее созданные записи сохранились.

## Блокеры реальных продаж

- **Платёжный провайдер:** не подключён и не прошёл проверку webhooks, возвратов, валют и идемпотентности.
- **Удостоверение личности:** ещё не реализованы email-верификация, восстановление доступа и безопасная процедура восстановления при потере факторов.
- **Инфраструктура:** требуются SSL/TLS на сервере, WAF/reverse proxy, ограничение соединений, внешние мониторинг и алертинг, проверенные восстановлением резервные копии.
- **Файлы:** локальный storage нельзя считать облачным постоянным хранилищем; необходим отдельный файл-сервис, антивирусная проверка и политика хранения.
- **Безопасность:** независимый аудит, эксплуатационная модель секретов, проверка доступности, нагрузочное тестирование.
- **Юридическая часть:** правила Standoff 2 и право продавать конкретные товары/услуги, персональные данные, оферта, возвраты, права потребителей.

Релиз v1.0.0 можно использовать для локальных и демонстрационных целей, пока эти вопросы не закрыты.

## Эксплуатационные показатели

Владельцу доступны:
- `/admin/operations` — показатели задач, обращений, заказов и платёжного журнала;
- `/admin/readiness` — диагностические факторы, выделенные как проверенные, предупреждения или блокеры;
- `/api/health` — минимальная проверка соединения с PostgreSQL без публикации секретов.

Наличие зелёных индикаторов не означает, что бизнес, сервер и пользовательские данные соответствуют всем требованиям законодательства и безопасности.
