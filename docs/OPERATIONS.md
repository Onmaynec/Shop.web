# Операционная панель StandoffShop

## Роли

| Роль | Каталог/заказы | Поддержка | Очередь | Управление ролями | Выгрузки |
|---|---|---|---|---|---|
| ADMIN | Полный доступ | Да | Да | Да | Да |
| SUPPORT | Нет | Да | Нет | Нет | Нет |
| FULFILLMENT | Только назначенные задачи и файлы | Нет | Да | Нет | Нет |
| CUSTOMER | Только свои заказы | Только свои обращения | Нет | Нет | Нет |

**Примечание:** покупатели и сотрудники должны иметь индивидуальные аккаунты. Форма выдачи прав доступна только владельцу с ADMIN. Самостоятельно изменить собственную роль через админку нельзя. Каждая смена роли отзывает прежние сеансы.

## Отчётность

Адрес: `/admin/operations`. Показываются агрегированные заказы последних 30 дней, состояния задач, активные обращения, возраст старой задачи и сумма событий платёжного журнала. Sandbox и прочие провайдеры строго разделены. Никакие данные не интерпретируются как реальная коммерческая выручка без сверки.

CSV: `/api/admin/reports/orders`, параметры `from`, `to` (YYYY-MM-DD по UTC) и необязательный `status`. Охват — максимум 93 дня; за один запрос максимум 5000 заказов. Значения, похожие на формулы Excel/LibreOffice, экранируются; выгрузки пишутся в аудит. Файл содержит email и состав товаров — соблюдайте режим хранения персональных данных.

Пример: `/api/admin/reports/orders?from=2026-11-01&to=2026-11-14&status=FULFILLED`.

## Выполнение заказов

При серверном подтверждении платежа создаются задачи по позициям заказа. Исполнитель назначает задачу себе, затем может менять её статус и загружать результаты. Загрузка разрешена только назначенному исполнителю, когда задача IN_PROGRESS или DONE, а заказ PAID/PROCESSING и подтверждение оплаты действительно.

`/admin/queue/<orderId>` — рабочее место назначенного сотрудника. Здесь нет email покупателя и административных функций публикации. Публикация приватного файла возможна только из карточки заказа под ролью ADMIN после завершения работ.

Оплата по-прежнему требует проверенного события от платёжного провайдера; sandbox существует только локально и отключён в production.

## Мониторинг и эксплуатация

`GET /api/health` проверяет связь с PostgreSQL. Здоровье системы не равно готовности к внешним продажам. Перед staging/release настройте регулярные резервные копии PostgreSQL, `MEDIA_STORAGE_DIR`, `PRIVATE_DELIVERY_DIR`, централизованный лог, мониторинг доступности и оповещения. Настройка этих внешних систем не входит в данную версию.

## Миграция

Сначала остановите сайт и сохраните резервную копию БД и локальных файлов. Из текущего Docker Compose-проекта:

```cmd
docker compose up -d
npm ci
npx prisma generate
npm run db:migrate
npm run db:status
npm run dev
```

Не удаляйте PostgreSQL volume. После миграции в существующей БД автоматически не назначаются новые роли: ADMIN и CUSTOMER остаются прежними.

## Ограничения предпродажной версии

Эквайринг, почтовые провайдеры, MFA, rate limit на reverse proxy, продакшен-object storage, юридическая документация и независимый security review всё ещё требуются перед коммерческим запуском.
