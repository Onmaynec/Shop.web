# StandoffShop — Catalog Pro (v0.7.0)

В v0.7.0 каталог переведён от одиночной карточки товара к структуре с изображениями, вариантами, характеристиками и подразделами. Сохранена монохромная дизайн-система.

## Товары

Адрес админки: `/admin/products`.

Карточка включает:
- Название, уникальный slug, описание, категорию и базовую цену (в БД копейки).
- Уникальный SKU/артикул (необязателен для базовой карточки).
- До 12 тегов и 16 пар характеристика/значение.
- До 8 изображений в галерее (каждое с alt-подписью).
- До 12 ценовых вариантов, каждый с уникальным SKU, названием и собственной ценой.
- Статус публикации DRAFT / ACTIVE / ARCHIVED.

**Предпросмотр:** `/admin/preview/<productId>` доступен только ADMIN, в том числе для черновиков. Публичная страница `/product/<slug>` доступна только когда продукт ACTIVE.

**Копирование:** кнопка в карточке переносит поля в новый черновик. Slug и SKU вариантов следует проверить на уникальность перед сохранением.

**Массовые операции:** на странице /admin/products выберите карточки и примените публикацию, черновик или архивирование. Одним API-запросом разрешено обработать до 50 ID. Операции сохраняются в аудите.

## Варианты и оформление заказа

Если активные варианты существуют, покупатель обязан выбрать один из них. Цена варианта не принимается на доверии из браузера: API заново читает variantId, сверяет принадлежность товару, статус варианта и стоимость. Ключ идемпотентности учитывает ID варианта.

Снимок `OrderItem` фиксирует:
- Базовое имя товара;
- Название выбранного варианта (`variantSnapshot`);
- SKU (`skuSnapshot`);
- `unitPriceKopecks` и `quantity`.

Изменение цены позже не меняет существующий заказ. Старые заказы остаются совместимыми: у них `variantId` и снимки вариантов равны NULL.

При удалении варианта из формы ранее сохранённый вариант *деактивируется*, а не удаляется из базы: старые заказы сохраняют ссылки на него. Вариант можно позже включить повторно через редактор. Для нового продукта без вариантов доступна базовая цена.

## Изображения

Администратор может:
- Загрузить PNG/JPG/WebP до 2 МБ через `POST /api/admin/media`;
- Добавить прямую HTTPS-ссылку;
- Задать alt-текст, переместить изображение выше/ниже, удалить из галереи (ссылка остаётся в медиахранилище до отдельной уборки).

Сервер проверяет MIME-type и байтовую сигнатуру, генерирует случайное имя и сохраняет файл в `MEDIA_STORAGE_DIR`, либо в `data/media` по умолчанию. Отдача файлов: `GET /api/media/<id>.<ext>`. SVG и произвольные типы файлов запрещены.

**Важно при деплое:** файловое хранение подходит для локального/self-hosted сервера, где есть постоянный том. Не используйте эпизодическое файловое окружение без внешнего хранилища (например, перезапускаемые stateless-инстансы) — загруженные файлы могут потеряться. Для production рекомендуется внешний object storage и отдельный media-adapter.

**Бэкап:** PostgreSQL **не содержит байты изображений**. Сохраняйте и восстанавливайте каталог `MEDIA_STORAGE_DIR` вместе с копией базы, иначе галереи перестанут отображаться.

Размер файла ограничен в приложении; на публичном сервере дополнительно установите лимит тела HTTP-запросов и соединений на reverse proxy. Оптимизация и сканирование изображений антивирусом отсутствуют.

## Категории и фильтры

Категории могут содержать подкатегории. Поддерживаются **два уровня** (корень → подкатегория), циклы и удаление непустой категории запрещены.

При выборе корневой категории каталог показывает её собственные товары и товары непосредственных подразделов. Фильтры: поиск по названию, описанию и SKU; категория; tag; диапазон цены; сортировка по дате, базовой цене или названию. Сортировка по цене использует **базовую цену** карточки. Для товаров с вариантами в карточке отображается минимальная цена активных вариантов. Фильтр диапазона учитывает подходящие активные варианты. Теги на страницах товара открывают фильтрованный каталог.

## Главная страница

`/admin/content` содержит редактор первого экрана: метка, две строки заголовка, описание, CTA и фоновое изображение. Раздел имеет живой предпросмотр. Изменения видны покупателям только после включения опции «Опубликовать».

Кнопка CTA может вести только на `/catalog`, `/account` или `/cart` — внешние перенаправления запрещены.

## Миграции

Переход с v0.6.0:
1. Остановите сайт.
2. Создайте резервную копию PostgreSQL; отдельно сохраните media-каталог.
3. Выполните `npm ci`, `npx prisma generate`, `npm run db:migrate`.
4. Выполните `npm run db:status` и `npm run dev`.

В v0.7.0 не удаляются ранее существующие таблицы. Новые поля старых записей допускают NULL или имеют значения по умолчанию. **Не удаляйте Docker-том PostgreSQL.**

## Проверки

- Unit: Zod-валидация SKU, ссылок, характеристик, вариантов, media-signature и адресов CTA.
- Integration: создание подразделов, загрузка PNG, предпросмотр черновика, bulk-публикация, выбранный variantId, неизменность цены старого заказа, аудит.
- CI: Prisma migrations, TypeScript, security audit, unit, production build и sandbox.
- Visual UI: каталог, карточки, админ-редактор, мобильная адаптация.

## Ограничения

Версия не включает управление складскими запасами, сложные скидки, продакшен-S3, обрезку изображений, автоматическую выдачу товара и эквайринг. Не публикуйте тестовые предложения как реальные.
